\section{Experimental Setup}
\label{ch6_sec:experimental_setup}
 
To evaluate the performance, robustness, and practical benefit of the implemented system, a structured experimental setup is defined. The evaluation is conducted under controlled conditions to ensure repeatability and consistency across all test scenarios. This section outlines the test environment, the selected scenarios, and the metrics used to assess system performance.
 
\subsection{Test Environment}
\label{ch6_sec:test_environment}
 
All experiments are conducted within the virtual environment used during system development. This ensures consistency between implementation and evaluation, allowing the behaviour of the system to be assessed under identical conditions.
 
The evaluation setup includes the complete system pipeline operating on simulated workpiece data. The environment enables controlled testing of different scenarios without external disturbances, ensuring that observed results are attributable to the system behaviour rather than environmental variability. This approach supports repeatable experimentation and reliable comparison across multiple test runs.
 
\subsection{Test Scenarios}
\label{ch6_sec:test_scenarios}  
 
To assess the adaptability of the system, a set of representative test scenarios is defined based on variations in workpiece geometry, initial placement, and execution complexity. These scenarios are designed to reflect the key operational challenges addressed by the system and to provide measurable evidence for the thesis objective of reducing manual programming effort through automated planning.
 
The evaluated scenarios include:
\begin{itemize}
\item Nominal feasible bending case
\item Arbitrary initial workpiece orientation
\item Workspace-constrained configuration
\item Regrip-required bending case
\item Opposite-side bending workflow
\item Failure-prone or infeasible configuration
\end{itemize}
 
Each scenario is executed ten times to verify that the system produces consistent and repeatable results under identical conditions. For the failure-prone scenario, the repeated trials are used to assess whether unsafe or infeasible cases are detected reliably before continuation.
 
\subsection{Evaluation Metrics}
\label{ch6_sec:evaluation_metrics}
 
The system performance is assessed using a combination of quantitative and qualitative evaluation criteria. The selected metrics are intended to verify whether the developed planning pipeline solves the thesis problem within the scope of the simulated study, namely by generating feasible robot programs automatically, adapting to varying workpiece conditions, and reducing operator-dependent programming effort.
 
The primary evaluation criteria include:
\begin{itemize}
\item \textbf{Execution success rate:} proportion of runs in which the complete robot program is generated and executed without manual intervention
\item \textbf{Mean planning time:} average time required to generate the robot program for each scenario
\item \textbf{Mean execution time:} average time required to complete the simulated bending task
\item \textbf{Mean number of regrips:} average number of intermediate reorientation operations required for successful execution
\item \textbf{Failure cases:} number of runs in which the system detects an infeasible or unsafe condition and prevents continuation
\item \textbf{Orientation, grip, and trajectory feasibility:} ability to maintain valid pickup orientations, grip configurations, and executable motion trajectories across the defined scenarios
\end{itemize}
 
In addition, qualitative observations are used to assess motion smoothness, stability of gripping, robustness of error handling, and the overall coherence of system behaviour during execution.
 
Together, the defined environment, scenarios, and metrics provide a consistent and comprehensive basis for evaluating the effectiveness of the implemented system.

\section{Functional Validation}
\label{ch6_sec:functional_validation}
 
This section evaluates the correctness of the core functional components of the implemented system. Each module of the planning pipeline is assessed based on its ability to produce valid and consistent outputs under varying input conditions. The validation focuses on confirming that the system behaves as expected and that the measured results reported later in this chapter are supported by correct module-level behaviour.
 
\subsection{Orientation Strategy Validation}
\label{ch6_sec:orientation_strategy_validation} 
 
The orientation strategy is evaluated using scenarios in which the workpiece is placed in arbitrary initial poses across different spatial regions. The results confirm that the system consistently determines a feasible pickup orientation for all tested configurations.
 
In cases where the initial orientation satisfies admissibility constraints, the detected pose is preserved. When this is not possible, the system successfully applies corrective transformations or fallback strategies to generate a valid orientation. Across all evaluated scenarios, a feasible pickup orientation is obtained without requiring manual adjustment, demonstrating robust handling of non-deterministic input conditions.
 
\subsection{Grip Planning Validation}
\label{ch6_sec:grip_planning_validation}
 
The grip planning module is validated by assessing its ability to generate stable and feasible suction cup placements under geometric and physical constraints. Test cases include variations in workpiece size and configurations containing internal cut-outs.
 
The results show that all selected grip configurations satisfy geometric constraints, including edge clearance and exclusion of hole regions. Furthermore, the force validation step ensures that only configurations with sufficient holding force are accepted. In multi-cup scenarios, the system consistently selects configurations that improve stability through appropriate spacing. These results confirm that the grip planner produces reliable and physically feasible solutions.
 
\subsection{Regrip Planning Validation}
\label{ch6_sec:regrip_planning_validation}  
 
The regrip planning strategy is evaluated using scenarios in which the initial configuration is not directly executable due to kinematic limitations. The results indicate that the system correctly identifies such cases and determines an alternative configuration that enables successful execution.
 
For all evaluated scenarios requiring regrip, the system selects a feasible orientation and completes the required reorientation sequence without failure. The number of regrip operations is minimized through the selection strategy, confirming that the approach avoids unnecessary intermediate steps while maintaining feasibility.
 
\subsection{Opposite-Side Bending Validation}
\label{ch6_sec:opposite_side_validation}
 
The opposite-side bending workflow is validated through scenarios that require bending operations on both sides of the workpiece. The evaluation confirms that the system successfully performs the flip operation and continues execution using the same planning pipeline.
 
After the flip, the system re-establishes a valid configuration and completes the remaining bending operations without inconsistencies. The results demonstrate that multi-stage operations are handled seamlessly, without requiring separate control logic for different workpiece orientations.
 
Overall, the functional validation confirms that all major components of the system operate correctly and produce consistent results across a range of test conditions. The evaluation demonstrates that the implemented system satisfies the core functional requirements defined in Chapter~\ref{ch:system-concept-methodology}.

\section{System-Level Performance Evaluation}
\label{ch6_sec:system_performance_evaluation}
 
While the previous section validated individual functional components, this section evaluates the performance of the complete system pipeline. The objective is to assess how effectively the integrated system operates under realistic conditions, considering execution efficiency, motion quality, and overall system behaviour.
 
\subsection{End-to-End Execution Results}
\label{ch6_sec:end_to_end_execution_results}
 
The system is evaluated using the test scenarios defined in Section~\ref{ch6_sec:test_scenarios}, covering nominal operation, orientation variation, workspace constraints, regrip handling, opposite-side bending, and failure-prone conditions. Across the majority of evaluated scenarios, the system successfully generated and executed complete robot programs without requiring manual intervention.

\subsection{Execution Time Analysis}
\label{ch6_sec:execution_time_analysis}
 
The execution-efficiency assessment considers how the computational effort for plan generation relates to the observed motion sequence in simulation. The measured planning times remain within a narrow range across all successful scenarios, indicating that the computational overhead of the planning pipeline is modest and stable.
 
The shortest mean planning time is observed in the nominal bending case, whereas the highest value occurs in the opposite-side bending workflow due to the additional flip and recovery logic. Mean execution time follows the same trend, increasing from standard handling cases to regrip-required and opposite-side cases. Even in the more complex scenarios, the increase remains moderate, which indicates that the added planning logic improves adaptability without imposing prohibitive execution overhead.
 
\subsection{Trajectory Quality and Feasibility}
\label{ch6_sec:trajectory_quality_and_feasibility}
 
Trajectory quality is assessed based on smoothness, continuity, and kinematic feasibility. The generated trajectories exhibit continuous motion without abrupt changes in direction or velocity. The use of interpolated waypoints and smooth motion profiles ensures stable execution.
 
Workspace constraints and singularity avoidance mechanisms prevent the generation of infeasible paths. When target poses approach the limits of the workspace, the system adapts the trajectory to remain within valid bounds. This confirms that the generated motions are both feasible and reliable for execution.
 
\subsection{Comparison with Manual Programming}
\label{ch6_sec:comparison_with_manual_programming}
 
To evaluate the practical benefits of the developed system, a comparison is performed between conventional manual programming using drag\&bot function blocks and the automated approach proposed in this work. The comparison focuses on the aspects most directly linked to the thesis objective, namely preparation effort, adaptability to changing workpiece conditions, and repeatability of execution.
 
In the manual approach, the operator defines individual motion steps, configures parameters, and ensures correct sequencing of operations. This process is time-intensive and depends strongly on operator expertise. In contrast, the developed system generates the complete robot program automatically based on geometric input and configuration data, recalculating the required workflow when the workpiece condition changes.

\section{Robustness and Failure Analysis}
\label{ch6_sec:robustness_and_failure_analysis}

 
In addition to functional correctness and performance, the robustness of the system is evaluated by analysing its behaviour under challenging and failure-prone conditions. This assessment is closely related to the Failure Mode and Effects Analysis (FMEA) presented in Section~\ref{sec:fmea}.
 
\subsection{Failure Case Evaluation}
\label{ch6_sec:failure_case_evaluation}
 
The system is tested under scenarios designed to trigger potential failure modes, including invalid workpiece placement, infeasible grip configurations, and workspace boundary violations. These cases correspond to the failure-prone scenario reported in Table~\ref{tab:evaluation_summary}. In each such case, the system detects the issue before or during execution rather than allowing unsafe continuation.
 
For example, configurations with insufficient vacuum holding force are rejected during grip planning, while unreachable poses are identified during trajectory generation. These validations prevent the execution of unsafe or infeasible motions.
 
\subsection{System Response to Errors}
\label{ch6_sec:system_response_to_errors}
 
When a failure condition is detected, the system responds by halting execution and notifying the operator through the human interaction interface. This behaviour ensures that errors are clearly communicated and prevents the continuation of unsafe operations.
 
The runtime error monitoring mechanism further enhances robustness by detecting execution-level failures and providing immediate feedback. This layered approach to error handling ensures that both planning and execution errors are addressed.
 
\subsection{Limitations of the System}
\label{ch6_sec:limitations_of_the_system}
 
Despite its robustness, the system exhibits certain limitations. The evaluation is conducted within a virtual environment, and therefore does not capture all real-world uncertainties such as sensor noise, calibration errors, or mechanical tolerances.
 
Additionally, the absence of full self-collision detection limits the ability to guarantee collision-free operation in highly constrained scenarios. These limitations highlight areas for future improvement and potential extension of the system.

\section{Discussion}
\label{ch6_sec:discussion}
 
The evaluation results demonstrate that the developed system provides a structured and automated solution for press brake bending. Compared to the approaches discussed in Chapter~\ref{ch:state-of-art}, the system eliminates the need for manually defined waypoint sequences for the evaluated scenarios and enables adaptive behaviour based on geometric input and configuration data.
 
The integration of orientation determination, grip planning, regrip handling, and trajectory generation allows the system to operate under a wide range of conditions. The quantitative results show high success rates in nominal, orientation-varying, workspace-constrained, and regrip-required scenarios, while the comparison with manual programming indicates substantially lower preparation effort and faster adaptation to change. This represents a significant improvement over conventional methods, which typically rely on fixed configurations and require manual intervention for complex tasks.
 
The system also achieves a high degree of modularity, as demonstrated by the layered architecture presented in Chapter~\ref{ch_5:implementation}. Each module performs a well-defined function and contributes to the overall pipeline, supporting maintainability and extensibility.
 
However, the evaluation also reveals limitations. The reliance on a virtual simulation environment means that the results do not fully reflect real-world operating conditions. Furthermore, certain aspects, such as advanced collision detection and dynamic force feedback, are not included in the current implementation.
 
Overall, the system addresses key gaps identified in the state of the art by providing an automated, adaptable, and modular solution. Within the scope of the virtual evaluation environment, Chapter~6 therefore provides evidence that the thesis aim has been met: the developed system can generate feasible robot programs automatically, adapt to representative variations in workpiece conditions, and reduce manual programming effort compared with a conventional workflow. At the same time, the identified limitations provide a clear direction for future development.
