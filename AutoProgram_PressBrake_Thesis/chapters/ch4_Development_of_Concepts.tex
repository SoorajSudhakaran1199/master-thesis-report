\section{Purpose and scope of concept development}
Concept development is an essential part of structured design, which consists of the design phase where different principles solutions are developed and evaluated before implementation. This is an essential part of systematic engineering design. By evaluating different options with respect to certain criteria before proceeding, the chances of selecting an inappropriate design path are minimized. REF The concept development phase is crucial for the success of the project, as it allows for the exploration of different design alternatives and the selection of the most suitable one based on a structured evaluation process.
\par The gap in the research, as identified in Section \ref{Summary of the State of the Art and Identified Research Gap}, reveals the absence of an effective systematic approach to automatically generate robot programs for press brake sheet metal bending. This approach should consider changes in workpiece geometry, gripping, re-gripping, and pre-execution pose, minimizing manual programming. The gap in the research is addressed in the form of measurable engineering objectives, as discussed in \ref{CH_3_System Concept and Methodology}, with respect to functional requirements FR-01 to FR-07 and non-functional requirements NFR-01 to NFR-05. This chapter presents three different strategies to fulfill these objectives.
\par Concept A proposes a guided teaching approach in which a structured software workflow supports the operator during conventional manual robot programming. Concept B proposes an automatic program generation system in which waypoint, grip positions , regrip sequences and opposite side handling strategies are derived automatically by evaluating the inputs configuration file , with communication to the robot runtime via WebSocket.\Cite{dragandbot_anyrobot_2025} Concept C is a CAD integrated offline programming in which a digital cell model is used to generate , validate and execute robot program within a simulation environment \cite{Siciliano2016Robotics},\cite{Pan2012Survey}
\par The concept decision is made using Weighted Sum Model (WSM), a quantitative decision support method in which evaluation criteria are assigned relative weights and each concept is scored against criterion. This method satisfies the requirement that concept selection must be based on structure rather than on qualitative judgment. The morphological box and preferences analysis methods are alternative methods, The WSM is selected because it enables simultaneous multi-criteria weighting and produces a single quantitative score for each concept, which ensures appropriate for comparing concepts.

\section{Concept A – Structured operator Workflow with Guided Teach in programming}
\label{Concept A – Structured operator Workflow with Guided Teach in programming}
\subsection{Methodological Framework}
Concept A retains the conventional teach pendant paradigm as the mechanism for defining robot motion and introduces a software-based layer that structures and sequences the operator interaction. In this method, the operator is guided through a step-by-step workflow that collects process inputs, including the desires bending sequences, bend side selection and current workpiece positions. The operator then executes each action directly via robot teach pendant or control interface using the function blocks.
\par This Concept is grounded in the established practice of teach pendant programming described in section\ref{Manual And teach pendant based robot programming}. As identified in the literature, teach pendant programming is reliable and widely used in structured manufacturing environment where part geometries and process parameters are fixed \cite{Siciliano2016Robotics}. The guidance layer introduced in this concept (A) reduced the risk of operator errors and provides a structured interface than unguided teach pendant operation, but it does not alter the fundamental that all robot position and waypoints are defined through direct physical interaction with the robot.
\par Regripping operation, orientation changes, full side bending operation for a rectangular sheet under this concept A remains the responsibility of the user to define and execute. The system provides instructional prompts but does not execute, validate or generate any waypoints and position data. No interface to the robot runtime environment is required beyond standard teach pendant connectivity. The system does not possess object tracking subsystems, evaluate geometric constraint, grip position calculations or assess kinematic feasibility before execution.

\subsection{System Structure}
\label{System Structure}
The system structure of concept A consists of two layers. A dialogue management layer runs on an external computer and presents the operator prompt through functional blocks or graphical interface by manual program generation. A robot controller layer receives waypoint generated manually by the operator through teach pendant and execute them. No intermediate computation layer for geometric reasoning, constraint evaluation, or motion generation exists between these layers. The architecture imposes no dependency on object tracking sensor data or trajectory generation interfaces.

\subsection{Critical Evaluation}
\label{Critical Evaluation}
Concept A straightforward to implement and compatible with any industrial robot controller without software modification. The operation of the system is fully transparent and observable by the operator, which reduces the risk of unreachable and kinematics error occur during the unreachable target pose. These characteristics make it suitable for low variety, structured production scenario where process parameters are stable across batches.
\par However , the fundamentals limitation if this concept are significant in the context of research gap ,programming effort is not yet reduced because knowledge of robot kinematics , tooling constraints , regripping strategies and bending sequence algorithm should need to applied by the operator for every session \cite{Siciliano2016Robotics}, \cite{Pan2012Survey}. Minor changes in sheet geometry , workpiece holder placement requires full re teaching of the affected trajectories , which contradicts the flexible objective stated  in section \ref{Problem-Definition-and-Objectives} \cite{Siciliano2016Robotics}, REF 26. Regripping operation and full side bending operations must ne manually planned , which introduces a chances of operator error and increase the cycle time .No pre execution validation of target poses is performed , kinematic configuration are  discovered only during the physical or virtual robot motion which leads to safety risk and a source of unplanned downtime \cite{Siciliano2016Robotics}.
\par The software guidance layer of concept A provides process management but no automation level, it addresses the unstructured operator workflow without addressing root cause, which is the requirement for manual position definition. Concept A does not contribute to the primary objective of automatic program generation and failed to satisfy most of the functional and non-function requirements defined in \ref{tab:functional_requirements}. and REF NFR.

\section{Concept B – Automatic Program Generation based on rules with Integrated Constraint Validation.}
\label{Concept B – Automatic Program Generation based on rules with Integrated Constraint Validation.}
\subsection{Methodological Framework}
Concept B proposes an automation level, rule based, automated program for generation system in which all robot waypoints, grip positions, regrip sequences, opposite side handling operations and strategies are derives automatically from geometric input parameters and a structures YAML configuration file: operator interaction is limited selection of required output selection before execution and confirmation of generated programs visually. No manual waypoint generation, direct teaching or any runtime operation or decisions are required during program execution.
\par The system communicates with the robot runtime through AnyRobot interface, a robotics application program (API) Developed by KEBA \textbackslash\ Drag and Bot GmbH that provides standardized method for controlling industrial robots from different manufacturers via WebSocket communication\cite{dragandbot_anyrobot_2025}. The planning Software operates as the WebSocket client, the drag and bot runtime act as the server. This architecture establishes a clean separation between the planning computation layer and robot execution layer, which is a recognized design principle \cite{Thramboulidis2013MDE} .
\par Workpiece pose data is retrieved in real time from drag and bot object tracking subsystem and processes by an orientation validation component , which determines whether the tracked sheet orientation is admissible for the planned bending operation by applying a three level priority strategy ,a side normalized orientation is evaluation first , followed by original tracked orientations by the object tracker and finally a 180 degree rotated strategy , when neither of the first two falls within the configurable window. This Three level hierarchy ensures that valid gripping orientations and positions are identified for any initial sheet placement on the cell floor, which eliminates the need for operator prepositioning. Before grip position calculation, the program validated the sheet position is within the robot cell. This is applied to avoid the kinematic reachability error occurred during the program execution. The zone-specific admissibility limits are specific limits are robot cells configuration are configured in the input sections and require no code modification when cell layout changes. This design decision satisfies NFR 02as defined in table \ref{tab:functional_requirements} and NFR 05 as defined in table REF TABLE NFR .
\par Grip position are computed by a parameterized grip planning component s that uses the sheet dimension, mass suction cup diameter , rated shear force and edge clearance margin which all are defined in the input configuration files :candidate grip position reevaluated against edge clearance and cup spacing constraints and against the vacuum holding force which is derived from the relationship between suction pressure , cup contact areas and dynamic loading during transport \cite{VacuumGripperModeling}.Grip feasibility is evaluated before kinematic reachability assessment, ensuring that only variable grip configurations are submitted to the motion generation layer. This ordering prevents unsafe handling states that would result from a grip position that is kinematically reachable but physically unable to reach the sheet during transport \cite{VacuumGripperModeling} .
\par When the current grip configuration does not allow the targeted pose to be reached, an automated regrip cycle is initiated. The cycle places the sheet on a designated orientation table, repositions the robot to reset and then regrasp the sheet at an orientation that restores full reachability. This regrips logic directly satisfies FR03 as defined in table \ref{tab:functional_requirements} .
\par Opposite side bending is also supported through this concept through a dedicated module that executes a structured sheet flip sequence. After all primary bending operations are completed, the program evaluates whether the operated has selected for opposite side bends. If so, the sheet passes to flip position through a coordinated sequence of motion, gripper activation, and object attachment operations targeting positions to flip the sheet. Afte the flip, the opposite bending sequence is executed under the same validation, including orientation normalization, grip feasibility evaluation and reachability assessment before the waypoints is generated. This enforcement of validation across both primary and opposite side bending operation ensures consistent safety behavior throughout th full step bending process \cite{Gupta1998SheetMetalBending}
\par The motion trajectories are generated in linear cartesian motion commands using minimum jerk velocity interpolation profile REF 16: This profile minimizes the third derivatives of position over the motion, producing smooth velocity transition between waypoint that reduce peak acceleration and gripper loading forces during sheet transport. This is requirement for maintaining vacuum grip stability under dynamic conditions \cite{VacuumGripperModeling}.
\subsection{system structure}
\label{system structure Concept B}
The structure of Concept B consists of Five layers as defined in section \ref{System-Architecture-and-Design}. The input and configuration layer that collects all required inputs for the programming. The geometry and constraints evaluation layer applies grip feasibility rules, edge clearance checks and zone-based orientation constraints. The planning and decision logic layer determines the execution strategy, which decides the program to be direct execution or regrip required execution or workpiece flipping strategy, based on reachability and orientation validity . The trajectory planning layer produces linear cartesian waypoints with minimum jerk velocity profiles. The safety and validation layer applies pre-execution pose check before the command is published to the robot runtime.
\par This WebSocket channel of the Any robot interface allows to connect all five layer to drag and bot virtual simulation run time \cite{dragandbot_anyrobot_2025} .The configuration-driven approach allows all process parameters to be trimmed from program logic, allowing the solution to tackle new workpiece geometries simply by modifying the content of configuration files. This was in direct satisfaction of non-functional requirement NFR-02 as described in Section \ref{non-functional-requirements}.
\subsection{Critical evaluation} 
\label{Critical evaluation Concept B}
Concept B is aligned with the research gap stated in Section \ref{Summary of the State of the Art and Identified Research Gap} for every dimension identified in the literature. Define waypoints, plan regrips, and sequence work on the opposite side automatically from geometric parameters instead. A pre-execution pose validator guards against unsafe execution states before motion starts. This allows for configuration driven architecture that can adapt to new part geometries without the need for source code changes. The concept design satisfies all seven of the functional requirements and all five non-functional requirements defined in Chapter 3.
\par The primary constraints that Concept B operates within are those identified within Section \ref{System-Constraints-and-Assumptions}. The system operates within a rectangular sheet geometry with fixed 90-degree bend angle constraints. The integration with the KEBA robot controller hardware, which is part of the KEBA robot driver layer within the drag and bot software stack \cite{dragandbot_anyrobot_2025}, is identified within the future work section and is not included within the scope of this thesis. All validation has been conducted within the drag and bot virtual simulation environment, which is discussed in this section. These constraints are explicit and not indicative of design flaws but, rather, define the scope within which the design concept operates.

\section{Concept C – CAD Integrated Offline Programming with Digital Twin Simulation}
\label{Concept C – CAD Integrated Offline Programming with Digital Twin Simulation}
\subsection{Methodological Framework}
Concept C proposes a computer aided design (CAD) integrated offline programming (OLP) approach in which a digital model of the sheet metal workpieces and the robot cell used to plan , generate and validate robot program in a simulation environment , without using physical robot interaction during the programming .The OLP  software evaluates bending sequences , grip positions and regrip programming, kinematic reachability and genreted robot program based on the CAD geometry of the workpiece and tooling .The generated programs are validated inside a simulation before transfer to the robot controller for execution.
\par This approach corresponds to the offline programming section \ref{Offline programming approaches for industrial robots}. Industrial Olp tools such as ABB Robot Studio ,KUKA: sim And FANUC ROBOGUIDE implement this approach and are used in industry for robot program generation in structured production environment \cite{Pan2012Survey} .The digital twin based evaluation and validation reduces the occurrence of risk by identifying unreachable poses and collision condition before real execution, which has been identified as significant advantage over the teach pendant programming. \cite{Bar2018VirtualCommissioning}
\subsection{System Structure}
\label{System Structure_CAD Integrated Offline Programming with Digital Twin Simulation}
This concept consist of four layers .A cad modelling layer provides digital representations of the robot , press brake , tools and workpiece .An OLP and simulation layer uses the URDF(Unified Robot Description Format) representations to plan the algorithm for robot program through built in kinematic solver .A post processing layer converts the generated programs into controller specific syntax’s robot controller layer communicates the program for exception. Accurate digital twin representation of all cell components are required at the modelling layer small errors in modelling the digital twin model propagate as execution error that require manual re programming during commissioning.\cite{Siciliano2016Robotics} \cite{Pan2012Survey}.
\subsection{Critical Evaluation}
\label{Critical Evaluation_CAD Integrated Offline Programming with Digital Twin Simulation}
Concept C offers meaningful automation advantages for structured, high-volume production environments where accurate cell models are available and OLP tool investment is justified. Simulation-based validation provides strong pre-execution assurance, and the approach is supported by mature commercial software \cite{Siciliano2016Robotics}\cite{Bar2018VirtualCommissioning}. These characteristics make it the dominant paradigm in industrial robotic bending automation at the time of writing.
\par For the scope of this thesis, Concept C presents three fundamental disadvantages that result in its rejection. First, the implementation requires accurate CAD models of the complete robot cells, including the robot, press brake, tooling, fixtures, and workpieces — which represents a substantial engineering preparation effort that is not available within the thesis timeframe. 
\par Second, commercial OLP systems involve high license fees while demanding expert-level instruction - resources simply unavailable within this project's constraints REF Engineering Design: A Systematic Approach . Besides cost, mainstream OLP platforms lack native compatibility with both the drag and bot simulation framework and the AnyRobot WebSocket system, which define the core setup targeted here \Cite{dragandbot_anyrobot_2025}. Connecting such a tool would mean building a bespoke bridge to the drag and bot engine - an extra burden unjustified by timeline or ambition. Taken together, these factors rule out Concept C entirely \ref{Structural Comparison of Concepts} Structural Comparison of concepts.

\section{Concept Decision-Weighed Sum Model (WSM)}
\label{Concept Decision-Weighed Sum Model (WSM)}
\subsection{Methodology}
\label{Methodology WSM}
The quantitative concept selection technique used is the Weighted Sum Model. Each evaluation criterion in the WSM is given a weight based on how important it is to the design objectives. Each concept is then scored against each criterion on a scale of 1 to 5, with 5 denoting full satisfaction and 1 denoting non-fulfillment. Each concept's overall weighted score is calculated by multiplying the corresponding score by each criterion weight. The idea that receives the highest total weighted score is chosen.

\subsection{Evaluation Criteria and Weights}
\paragraph{Programming Effort Reduction (25\%)}-This criterion carries the highest weightage because it directly addresses the primary research gap. This makes automation easier by reducing a lot of manual programming especially when parts change frequently. This gap is consistently identified in literature as the most significant barrier to increased automation in robotic bending cells.
\paragraph{Automated Regrip and Opposite-Side or sheet flipping Support (20\%)}: According to Section \ref{Robotic Sheet-Metal Bending and Press-Brake Cells}, the most difficult and time-consuming parts of robotic press brake bending that are not sufficiently handled by current methods are regripping and opposite-side handling. The criticality of FR-03 and FR-05 is reflected in this weight. 
\paragraph{Pre-Execution Pose Validation (20\%)}: Before robot motion is started, infeasible poses must be identified in accordance with safety regulations NFR-03, NFR-04, and NFR-05. In robotic bending cells, executing unreachable target poses is a major source of system failure as well as a safety risk.
\paragraph{Flexibility for Changing Part Geometries (15\%)}: One of the main goals derived from the research gap is the capacity to adjust to new workpiece variations without reprogramming. NFR-02 is directly satisfied by configuration-driven adaptability, and the 15\% weight indicates that this is a secondary goal following the primary automation requirements. 
\paragraph{Feasibility of Implementation within Thesis Scope (10\%)}: The evaluation must consider as the practical limitations of a master's thesis, such as time constraints, software access, and hardware resources. Regardless of its theoretical merits, a concept that cannot be realized within the scope of the thesis cannot fulfill the research objectives.
\paragraph{Operator Usability (10\%)}: Non-functional requirement NFR-01 says that the system must be usable by non-expert operators with little interaction during normal operation. The 10\% weight shows that usability is an important quality attribute, but it is not as important as the main automation requirements.

\section{Analysis of results and Concept Decision}
\label{Analysis of results and Concept Decision}
The score of 5.00 indicates that Concept B meets all six criteria at the highest level possible. The automatic derivation of waypoints from geometric parameters eliminates the need for programming effort. The only input required from the operator is to choose the bend side and confirm execution. Regripping and opposite-side bending are fully automated through dedicated software modules that realize gripper IO control, object attach and detach sequencing and multi-step rotation, all under YAML-configurable parameters [13]. Prior to the motion command being generated, the pose validation in the execution is performed using two independent components, namely the orientation validation module and the spatial zone classification module. The requirement of having flexibility in geometry is satisfying using YAML file. The Python implementation in the drag and bot virtual simulation environment can be done within the thesis. The operator interface is dialog-based and meets the requirement for usability by limiting operator interaction to essential pre-execution selections.
\par The Weighted Sum Model gives Concept A, total weighted score of 1.40, Concept B a score of 5.00, and Concept C a score of 2.70. Concept B gets the highest score by a wide margin, so it is chosen as the idea to be worked on and put into action.
\par Concept A scores a total of 1.40, which indicates that it does not meet the five most critical criteria. The fact that it scores 4 on implementation feasibility indicates that it requires minimal development effort, and the fact that it scores 2 on usability indicates the presence of the structured dialog layer. However, the fact that it does not have the capability for automation means it does not contribute to the achievement of the research objective and the identified gap. Qualitatively, it can be noted that it is easier to implement, but this is not enough when the goal is to have an automated system .
\par Concept C obtains a score of 2.70, which is a result of the partial fulfillment of three criteria: the generation of waypoints, pre-execution validation, and flexibility, all through the CAD-based planning and simulation process. The inability to integrate with the drag and bot virtual environment, the need to utilize commercial OLP software not within the scope of the thesis, and the need to have accurate cell CAD models all detract from the scores obtained in the areas of regrip automation, implementation feasibility, and usability by the operator. The total score obtained by Concept C, 2.70, confirms that this concept, though appropriate for large-scale industrial applications, is not appropriate within the context of this thesis.
\par In this chapter, three conceptually different approaches to the automatic generation of programs for robots in the process of sheet metal bending using a press brake were developed and validated. The development process was carried out according to the systematic engineering design methodology described in Pahl and Beitz \cite{Pahl2007EngineeringDesign}, so that the selection of the concept is supported by evaluation criteria defined and weighted according to the functional and non-functional requirements described in Chapter \ref{CH_3_System Concept and Methodology}.
\par Concept A, which is a guided teach-in with operator workflow, was developed and rejected because it does not decrease the amount of programming required, nor does it offer automated constraint validation, regrip support, and pre-execution pose checking. It does not meet the primary functional requirements of FR-01, FR-03, FR-05, and FR-06 as defined in Table \ref{tab:functional_requirements}
\par The CAD-integrated offline programming approach with simulation-based validation, i.e., Concept C, was proposed and rejected for its need for commercial offline programming tools and digital cell models, which are not available under the scope of the thesis, and for its inability to integrate with the drag and bot environment and any robot interface, i.e., the proposed development environment.
\par The automatic program generation rule-based system with integrated constraint validation, Concept B, was chosen based on the Weighted Sum Model with a total weighted score of 5.00. Concept B directly deals with all dimensions of the research gap because it automatically derives waypoints based on geometric parameters, automatically generates regrip sequences and opposite side bending with the aid of specialized software modules, and validates admissibility and reachability constraints before any movement takes place, all while communicating with the runtime environment of the robot using the authenticated AnyRobot WebSocket interface \cite{dragandbot_anyrobot_2025}.
