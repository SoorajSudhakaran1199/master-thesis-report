\section{Manual And teach pendant based robot programming.}
\label{Manual And teach pendant based robot programming}
The programming of the industrial robots follows a programming approach based on teach pendant programming, which means, the robot movement and motions are explicitly defined and programmed directly during the operations. The programmer subsequently uses this approach to position and then programs the robot to move to a series of specific target positions. 
The robot subsequently saves these positions using programming languages specific to each robot type and brand. Despite advances in programming approaches for robotics systems, this method is still commonly used to its owing to its reliability and its usefulness in interacting with real world systems \cite{Siciliano2016Robotics}
. However, this may require expert knowledge of the robot’s kinematics, tooling, and process constraints. Minor changes in geometry, fixture placement or cell layout often involve extensive manual reprogramming, increases commissioning effort and system downtime. Therefore, teach pendant programming scales poorly in flexible manufacturing systems characterized by frequent changeovers coupled with small batch sizes. In terms of the sheet metal handling and the automation of the press brake operations, the restrictions can appear even more considerable. 
When working with these pieces of sheet metal that can be flexible and large in size, their handling involves further challenges that need to be addressed, revolving around reachability issues and collision avoidance. In terms of manual programming , each step of the planned process of the bending involves the precise determination by the user of the intermediary positions for each action of the manipulator necessary for the accomplishment of the task at hand .Such an approach can appear heavily dependent on the users expertise for the purpose of avoiding the iterative try and error approach that might be inevitably required during the plant operations \cite{Aomura2002RoboticBending} .Especially , more classical robot programming paradigms have be identified as insufficient in terms of abstraction and flexibility needs for current applications in industrial robotics, especially when high flexibility and fast reconfiguration are at stake \cite{Siciliano2016Robotics}
.Such an approach to programming the robot , through interaction with the teach pendant itself , tend to create program that are more dependent on the specific type of the robot used and also the cell configuration, programming style of each particular operator etc.
\par As a result, manual teach in pendant programming methods have traditionally been seen to be unsuitable for advanced automation tasks. that often requires increased flexibility, analyses of process knowledge, and minimization of human interventions. It is realization that sparked off interest in alternative offline programming, task level programming and even methods of automatically generating robot programs, as discussed in the sections \cite{Siciliano2016Robotics}

\section{Offline programming approaches for industrial robots}  
\label{Offline programming approaches for industrial robots}
The disadvantages associated with manual programming of industrial robotic arms lead to an increase in the uptake of offline programming in industrial applications. This programming method led to running the digital working environment using digital models of robots, tools, grippers and other components used for the programming without interrupting the real production. \cite{Siciliano2016Robotics}
\par This programming is based on Computer aided Model $\text{(CAM)}$ also known as the geometric or CAD models, which represent the robots, workpiece and all other components. These models allow robot programs to be simulated before they implement in the real working environment. Despite being associated with the disadvantages, offline programming also has some limitations when used in industrial applications.\cite{Pan2012Survey}
\par In robot- assisted sheet Metal handling presses brake operation, offline programming is commonly used for robot programs such as sheet metal handling, bending process, pick and regrip operations for sheet in different bending stages. Using virtual simulation, engineers can evaluate, validate and verify , and can identify the if the robot's reachability, regripping positions and bending sequences while safely avoiding the unreachable path to machines and fixtures. \cite{Aomura2002RoboticBending}.
Even though this program offers many benefits, it relies heavily on exact digital models of robot cells. If the digital model does not perfectly match the real model configurations, due to the calibration error, fixture errors or in change in tool geometry model, the robot may misbehave in kinematics. In such cases, manual re- configuration needed, engineers must re-program during the commissioning. Another limitation of this programming is that it is less suitable for the environment with frequent changeovers and high-end product variety \cite{Siciliano2016Robotics}
This occurs because the programs are usually created for specific tasks and robot paths for, specific part geometry and bending process. \cite{Pan2012Survey}
In case multi side bending process, regripping and regrasping operation is required, often require the workpiece to be temporarily place in orientation table and then grasped again in a different configuration. This is necessary to avoid collision with and optimize the robot kinematics. In this programming, these approaches are checked by the programmer, which increases the engineering effort that leads to limiting flexibility and time consuming. \cite{Aomura2002RoboticBending}.
\par In summary, this program provides clear advantages and over manual programming by reducing the on-site teaching time and enabling virtual validation robot waypoints. However, it depends heavily on exact digital model and manual definition of task sequences reduces the efficiencies in industrial applications. These limitations have motivated into high level research, task oriented automatic program generation strategies, which aim to reduce human involvement while increasing the adaptability of the system. These approaches are explained in the following sections. 

\section{Automatic and Rule-Based Robot Program Generation}
To reduce further engineering effort associated with manual and offline programming such as manual programming and offline programming, research in industrial robot section has increasingly focused on automatic program generation. This in-depth research aims to derive executable high level automated tasks with respect to robotics position and geometric information, thereby minimizing direct human re programming. In contrast to traditional offline programming, where engineer defines the motion trajectories, automated programming seeks to capture the environmental details in reusable and systematic representations.\cite{Siciliano2016Robotics,Pan2012Survey}.
\par A prominent solution executed in this method is rule based and task level robot program generation. In such methods, predefined rules or tasks are used to resolve the high-level constraints related to kinematics, tool orientation, and process feasibility. This rule-based programming reduces the operator role and enable the robot to perform intelligently for recurring task in industrial environment \cite{Pan2012Survey,Kruger2009SkillBasedRobotics}. Several researchers have been used reusable primitives as a foundation for automatic robot programming. Rather than programming individual motions, these complex robot behaviors represent a meaningful action such as grasping, repicking, or approaching target positions. \cite{Kruger2009SkillBasedRobotics,Schou2013SkillBasedProgramming}. Automated programs is supported by geometric and feature based representation of parts such CAD Models or simplified geometric descriptions used for detecting or identifying the features such as grasping edges for the mechanical operations, approach directions, task sequences can be processed automatically. As compared to manual and conventional programming methods, this method enables adaptations to complex product variants. \cite{Bjorkelund2012KnowledgeBasedProgramming}.
This automated program generation has also been invented for sheet metal handling and robotic press brake automation applications, where repetitive task for bending operations and geometry is usually structured. In such systems, bending sequences, grasp configurations and placement strategies are derived from the constraints and geometric models rather than manual teaching. This reduces the engineer’s effort and gives highly efficient output for repeatable similar workpieces. \cite{Aomura2002RoboticBending,Gupta1998SheetMetalBending}.
\par Despite these advantages, rule-based robot program generations lead to some limitations. Most systems relay simply on the assumptions regarding part geometry, fixture layouts, tooling position and trajectories generations, which lead to restriction on applicability in highly variant part processes and low volume production scenarios. As task complexity increases, the number of rules may also get increased, which makes it hard to maintain the system, difficult to scale and lead to inconsistencies. \cite{Siciliano2016Robotics,Kruger2009SkillBasedRobotics}.
Regripping operations is one of the most highlighting problems in the sheet metal handling process. For multi-step bending , robot need to place the workpiece on temporary place called orientation  table , which is used for the repegging and repositioning the workpiece for next sequence bending .Although there exist some regripping strategies , these are particularly for some specific tools and specific robot cells. \cite{Aomura2002RoboticBending,Gupta1998SheetMetalBending}. As a result, they do not support other setups well and limit the chances of automation.
\par Automatic program generation has also been combined with optimization-based methods, where trajectory quality is considered during motion generation. Such methods improve the execution performance with generating trajectory plans in robot handling tasks \cite{Glorieux2018TrajectoryOptimization}.
\par In conclusion, automatic and rule-based programs subsequently reduce the engineer's effort and increase consistency for complex task specifications. However, some approaches are still considered as the limitations, limited adaptability to process different variations about geometry and handling. These limitations give motivation to develop specific solutions with high degree automation, specifically for the sheet metal bending, which is the focus of this research. 

\section{Robotic Sheet-Metal Bending and Press-Brake Cells}
Robotic press brake sheet metal bending has gained attention in industry due to the increasing demand for high productivity and consistent bending quality. In such systems, industrial robots are capable to handle sheet metal workpieces throughout the bending process, including gripping, positioning at the press brake for bending process, reorientation for subsequent bending sequences and unloading process after the process completion. Compared to manual bending, robotic system reduces the operator’s effort while ensures precise bending quality in a repeatable and reliable way. \cite{Siciliano2016Robotics}
Early research focused on analyzing feasibility of integrating industrial robots with traditional press brakes systems. These studies demonstrate that the sheet metal bending can be effectively performed when robot waypoints are carefully coordinated with the bending operation sequences. These results highlighted the importance of reliable synchronization between the robot and the press brake, particularly for precise process execution and accurate motion planning. \cite{Aomura2002RoboticBending}
\par Later studies of robotic sheet metal bending processes by researchers addressed the problem of process plaining, including the determination of bending sequences, selection of which tools need to be used for the specific bend and handling strategies for the workpiece. As a result, they showed bending depends on the geometry, reachability to process the bends. So, they found out that, make planning to make aware of unstable grasps or robot motions that cannot be executed during the process. \cite{Gupta1998SheetMetalBending}
Unlike the rigid workpiece, the sheet metal continuously changes the shapes after each bending operation. This requires the robot to adjust the gripping position and adopt different orientational pickup through the process. To ensure safety, many robotic systems rely on conservative motion planning and fixed handling strategies. While this approach reduces the system complexity when dealing with the complex or varying part geometry. \cite{Aomura2002RoboticBending,Siciliano2016Robotics}
On the next stage, regripping becomes one of the most challenging parts for robotic bending. Often the sheet must be temporarily placed at an intermediate location and then repick again for the next bend, requiring appropriate regripping positions that are compatible with the bending tools. most existing systems rely on predefined regripping locations and manually planned regripping strategies. This significantly increases engineering effort and make system adaptability difficult for frequent process changes . \cite{Aomura2002RoboticBending,Gupta1998SheetMetalBending}.
\par Research on path planning for robot assisted sheet metal bending shows constraints on their trajectories around press brake and tooling represents a major challenge. The waypoints must be carefully review in between the workspace especially during the reorientation and regripping operations \cite{LiaoWangSheetMetalBending}.
\par Additional studies highlighted the role of grasp feasibility and stability, especially when vacuum based gripper are used. Research on vacuum gripper modelling and automatic grasp positions strongly depend on robustness and efficiency. \cite{VacuumGripperModeling}. However, these approaches tailored to specific designed gripper types or handling strategies, and they are integrated into an automatic program generations press brake industrial applications

\par In industrial practice, robotic press brake bending performs well when the part geometry, tooling and process parameters are predefined. Such system typically relies on expensive offline preparation, accurate digital model simulations, manually defined handling and regripping strategies. However, as product variety increases, system flexibility significantly decreases.
Consequently, the robotic press brake bending is well suited for structured and repetitive process. Nevertheless, current system still depends heavily on predefined process knowledge, pre planned trajectories and manually configured regripping strategies. These limitations reduce adaptability and have motivated extensive research into automated robot program generation methods that can respond to changing processes and production conditions. \cite{Siciliano2016Robotics,Gupta1998SheetMetalBending}.

\section{Summary of the State of the Art and Identified Research Gap}
The research has shown that the evolution of robot programming has evolved overtime. Early approaches use manuals teach pendant programming, followed by offline programming and recent development of automated and rule-based programming methods.
Manual programming and offline programming are still widely used due to the robustness and direct physical interaction offered by programming. However, these methods require expert knowledge and therefore provide limited flexibility in industry. Offline programming optimizes some of these limitations of manual programming by enabling virtual simulation, but it remains limited by accuracy of digital model and need for manual defined task sequences.  Automate rule-based program generation methods aims to reduce engineer efforts by enabling higher level system process which increases the consistency and modularity in robot programming. Nevertheless, these approaches rely on predefined rules and conservative planning assumptions, which restrict their applicability in highly variant production scenarios.
\par In the context of sheet metal bending and press brake automation, these limitations are prominently highlighted. The regripping, reposition workpiece for multiple bend on different sides significantly affects the reachability and grasp feasibility. Current robotic system therefore depends heavily on manually planned regripping strategies and pre-defined trajectory planning. As a result, adaptability to new part geometry remains limited, bending sequences lack flexibility and systematic reprogramming is still required when process conditions change.
Consequently, there exists a gap between existing robot programming approaches and the requirements of flexible robot sheet metal bending applications. There is a lack of methods that enable automatic program generations capable of addressing these constraints, reducing programming time, and allowing non experts operators to configure and execute bending processes. Addressing this gap is essential for increasing flexibility and adaptability in modern robotic industry
